# utk_handhold: issues and requests

This repository is where you report bugs, ask questions and request features for **utk_handhold**, a FiveM resource
that lets players hold hands while they stand, walk and run: hand in hand in rows and rings of any size, and both hands
face to face.

**There is no code here.** The resource is sold separately and is protected by Cfx.re Asset Escrow. Please do not
post any part of it here: not the protected files, and not the files you are allowed to edit either.

## Installation and guide

[GUIDE.md](GUIDE.md) is the resource's own README: requirements, installation, every setting, the interaction
systems and frameworks it works with (with examples for your own), the exports and events for other resources, debug
mode and pose tuning, and troubleshooting. It describes the version named at its top.

## Before you open an issue

1. Check that you run the latest version. The version is in `fxmanifest.lua` and at the top of the resource's
   `README.md`.
2. Read the [guide](GUIDE.md), above all its **Troubleshooting** section.
3. Search the [open and closed issues](../../issues?q=is%3Aissue) in case it has been reported already.

## Opening an issue

Choose one of the forms on the [New issue](../../issues/new/choose) page:

- **Bug report**: something does not work as the README says.
- **Feature request**: something you would like the resource to do.
- **Integration request**: support for a framework, target system or other resource that is not covered yet.
- **Question**: anything else about setting it up or using it.

A good bug report says what you did, what you expected, what happened instead, and includes the errors from the server
console and the F8 console. Screenshots or a short clip help a lot with anything visual, such as how the hands look.

## Please do not post

- License keys, Cfx.re account details, server IP addresses or passwords.
- The resource's files or any part of them.
- Personal information about your players.

Leaked or resold copies of the resource get no support.

## Response times

This is maintained by one person. Every issue is read, but answers can take a few days.
